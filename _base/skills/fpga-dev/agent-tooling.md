# Агентские инструменты на этом проекте — числа и особенности

Как пользоваться инструментами — в отдельном навыке
`../rtl-agent-tools/workflow.md`; откуда их взять — `../rtl-agent-tools/install.md`.
Здесь только то, что относится к нашему RTL.

Измерено 2026-08-08, ветка `R120M.BF2_enc_passport`, топ
`R120M_BM2BF1X1_brd_ifm`, 868 файлов `.v/.sv`, ~45 000 строк.

## Что это даёт против нашего текущего цикла

Эталонный кейс — `src/main/R120M_BM2BF1X1_cmd_spi_tb.sv`, тестбенч бага
командного SPI (МК в mode 0, ПЛИС в mode 1, адрес `0x438` читался как `0x870`).
По записи в `workflow.md` этот баг стоил десяти циклов «сборка + прошивка».

| Что | Число |
|---|---|
| Симуляция ТБ без дампа | 44.0 с |
| Она же с `vcd add -r /*` | 83.7 с (+90 %), 613.6 МБ, 6786 сигналов |
| `vcd2fst` (однократно) | 7.2 с → 23.3 МБ (26×) |
| Запрос wavepeek по VCD / по FST | 2.1–2.2 с / **0.17–0.22 с** |
| Объём ответа на запрос | 132–1393 байта |
| Наивный полный скан VCD питоном | 16.8 с плюс написание скрипта |
| `slang` элаборация всего топа | 2.1 с (против ~40 с `vlog`, 5–6 мин синтеза) |
| Граф `slang-netlist`, 905 регистров | 0.2 с; запрос `--drivers`/`--fan-out` 0.2–0.3 с |
| Тот же вопрос цепочкой из 6 `grep` | 2.5 с и 48 405 байт выдачи (~80× по контексту) |

Ответ на баг получается одним запросом за 0.19 с — видно сдвиг на бит:

```
@5806490ns addr_u32=32'h70000004
@5851190ns addr_u32=32'h00000870      # вместо 0x438
```

Выигрыш не в первом вопросе, а в десятом: сегодня новый внутренний сигнал =
правка ТБ плюс 44 с пересимуляции; с дампом — 0.2 с на запрос.

## Флаги совместимости, без которых наш RTL не элаборируется

Нужны и для `slang`, и для `slang-netlist`, и для `read_slang` в yosys:

```
--std 1800-2017 --timescale 1ns/1ps --top <top>
--allow-use-before-declare
-Wno-multiple-always-assigns -Wno-mixed-var-assigns
```

Флагом не лечится: `19'({<<8{data_16b[0 +: 3]}})` в `MCU_FPGA.sv:141` — cast над
streaming-конкатенацией slang не принимает даже с
`--allow-self-determined-stream-concat`, а ModelSim и Gowin принимают.
Единственное такое место в проекте; для прогона инструментов переписывается во
временную переменную в копии дерева, RTL проекта не трогать.

Топ `main` нельзя брать как top у slang: у него интерфейсные порты. Брать
`R120M_BM2BF1X1_brd_ifm` и подкладывать заглушку `o_pll_10_50`.

## Находки статики в нашем RTL (2026-08-08)

Найдено за секунды; ни ModelSim, ни Gowin ошибками это не считают. **Ни одна не
проверена на железе — это кандидаты на разбор, не баги.**

| Файл | Что | Оценка |
|---|---|---|
| `linear_interpolation.sv:84` | `v3 = ~v3 + 1;` блокирующим в `always_ff`, где `v3` рядом присваивается через `<=` | настоящий смешанный стиль, риск рассогласования симуляции и синтеза |
| `lidar_conductor.sv:52,57,67` | `SM_pause_counter` пишется макросом `PAUSE_S` (task с output-аргументом = блокирующая семантика) и рядом через `<=` | тот же класс; идиома работает в продукте, но помечена всеми тремя инструментами |
| `sync_table_mem.sv:30` | `mem` пишется из `always_ff` и из `$readmemh` | ModelSim тоже ругается (vsim-3839), но в шуме из 55 warning не видно |
| `MCU_FPGA.sv:103,106,109,110,195,196` | тот же класс на полях интерфейса | требует разбора |
| `dpll_nco.sv:46` | использование `phase_accum` до объявления | нарушение LRM, ModelSim прощает |
| `angle_calculator.sv:31` | `inout`-порт нельзя инлайнить | ограничение yosys-slang (sv-elab #143), не наш дефект |

## Проверка эквивалентности: подтверждено на нашем модуле

`dpll_nco.sv`, полный цикл «поправил линт → доказал, что не сломал»:

- фикс линта (объявление `phase_accum` выше использования) — `eqy`
  **7/7 партиций PASS за 5.4 с**;
- негативный контроль (`>=` → `>` в условии выстрела NCO) — **3/7 FAIL за 4.9 с**,
  ровно на затронутых выходах `out_period`, `out_stb`, `phase_accum`;
  остальные PASS. Проверка не резиновая и локализует изменение.

## Чего эти инструменты про лидар не скажут

Связность, значения в дампе и эквивалентность двух версий RTL — да. Правильность
по физике (сдвиг сектора, разнос точек зеркал, задержка угла, паспорт энкодера)
— нет: там правильность считается по эталону на стенде, и доказательство только
железное. Правила эвиденса — в `workflow.md`.
