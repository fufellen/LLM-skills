# W5500 — Ethernet для R120M: MSOP TCP силами ПЛИС

Архитектурная цель: на R120M.BM2BF1X1 поток MSOP, который раньше уходил по
SPI на STM32 (и наружу через его сеть), отдаёт сама ПЛИС — soft-MCU DarkRISCV
управляет WIZnet W5500 (аппаратный TCP/IP-offload) по SPI. LwIP/RMII-стек
ветки ext_ram при этом не нужен: TCP/UDP-сокеты реализованы кремнием W5500.

Источники: даташит W5500 (WIZnet), официальный драйвер
<https://github.com/Wiznet/ioLibrary_Driver> (`Ethernet/W5500/w5500.h` —
все константы; проверено 2026-07-03).

## Чип в двух словах

- SPI до 80 МГц, 8 аппаратных сокетов, 16 КиБ TX + 16 КиБ RX (по умолчанию
  2 КиБ на сокет), TCP/UDP/MACRAW.
- SPI-кадр (VDM): 2 байта адреса + control byte
  `{BSB[4:0], RWB, OM[1:0]}` + данные с автоинкрементом, пока CS низкий.
  RWB: 1=запись, 0=чтение. OM=00 — переменная длина (VDM).
- BSB: 0 = общие регистры; сокет N: регистры `1+4N`, TX-буфер `2+4N`,
  RX-буфер `3+4N`.
- Общие регистры: MR 0x0000, GAR 0x0001, SUBR 0x0005, SHAR 0x0009,
  SIPR 0x000F, VERSIONR 0x0039 (**читается как 0x04** — тест живости).
- Регистры сокета: Sn_MR 0x00 (0x01=TCP, 0x02=UDP), Sn_CR 0x01,
  Sn_IR 0x02 (RW1C; SEND_OK=0x10, RECV=0x04), Sn_SR 0x03, Sn_PORT 0x04,
  Sn_TX_FSR 0x20, Sn_TX_WR 0x24, Sn_RX_RSR 0x26, Sn_RX_RD 0x28.
- Команды Sn_CR: OPEN 0x01, LISTEN 0x02, CONNECT 0x04, DISCON 0x08,
  CLOSE 0x10, SEND 0x20, RECV 0x40.
- Статусы Sn_SR: CLOSED 0x00, INIT 0x13, LISTEN 0x14, ESTABLISHED 0x17,
  CLOSE_WAIT 0x1C, SOCK_UDP 0x22.
- TCP-сервер: Sn_MR=TCP → Sn_PORT → OPEN → (SR=INIT) → LISTEN →
  ждать SR=ESTABLISHED → передача: писать в TX-буфер по Sn_TX_WR,
  Sn_TX_WR += len, SEND, ждать Sn_IR.SEND_OK (и чистить его).
- Приём: Sn_RX_RSR > 0 → читать с Sn_RX_RD → Sn_RX_RD += len → RECV.

## Подключение на R120M.BM2BF1X1

- W5500 (D8) на SPI ПЛИС при запаянных J10..J15 (альтернатива J22..J27 —
  MCU SPI1). Пины ПЛИС: SCLK=N2, MOSI=M2, MISO=N1, ~CS=P1, ~INT=M1, ~RST=L2.
- **~RST подтянут к GND (R58)** — пока ПЛИС не поднимет `WIZNET_RST_N`,
  чип выключен. ~CS/~INT подтянуты к +3V3_W.
- Схема подключения к soft-MCU (проверена симуляцией 2026-07-03):
  общая bit-bang шина SPIBB (как у FLASH в lwipdemo): MOSI=OPORT[0],
  SCK=OPORT[1], CS флеша=OPORT[2], EN=OPORT[3], MISO=IPORT[6];
  **CS W5500 = OPORT[8], RST W5500 = OPORT[9]** — прямые биты OPORT.
  В прослойке платы: `WIZNET_CS_N = soc_oport[8]`,
  `WIZNET_RST_N = soc_oport[9]`, SCLK/MOSI — те же пины, что и у флеша,
  `SPI_MISO` мультиплексируется по активному CS
  (`!WIZNET_CS_N ? WIZNET_MISO : FLASH_SPI_SO`).

## Симуляция (ПРОЙДЕНА 2026-07-03)

- Модель: `soft_mcu/dark_risc/sim/w5500_model.sv` (SPI slave + регистры +
  socket0 TCP + TX-буфер; после LISTEN сама «подключает клиента»; на SEND
  проверяет маркеры MSOP FF FE / FF 9B).
- Прошивка: `src/w5500demo/` — bit-bang драйвер + MSOP-строитель
  (формат 1в1 как lidarsim: 180 точек, 758 байт).
- Запуск:
  ```powershell
  make -C .../dark_risc/src clean all APPLICATION=w5500demo NOBANNER=1 CCPATH=...
  $env:DARKSIMV_DEFINES='+define+SPI +define+SPIBB +define+DARKWIZNET_SIM'
  $env:DARKSIMV_NOWAVES='1'
  vsim.exe -c -do "do .../dark_risc/sim/darksimv_modelsim.do; quit -f"
  ```
- Критерий PASS: `w5500 version=04`, `netcfg ok ip=c0.a8.02.f0`,
  `sock0 listen port=c3b4`, `established`,
  `w5500 model: msop frame ok len=758 count=1..2`, `w5500demo ok`.
- После экспериментов вернуть прод-прошивку:
  `git -C soft_mcu/dark_risc restore -- src/darksocv.mem`.

## Грабли (найдены при отладке симуляции)

- **DarkRISCV/gcc: `(value >> bit) & 1` с переменным сдвигом дал на шину
  арифметическое ОТРИЦАНИЕ байта** (0x39 → 0xC7 = −0x39). Рабочий идиом —
  как в flash-драйвере lwipdemo: `value & (1u << bit)`. Root cause на
  уровне ISA/кодогенерации не разбирался — просто не использовать `>>`
  с переменным сдвигом в битовых конвейерах без проверки.
- `spi_master_bb` защёлкивал MISO в IPORT только при своём CSN=0
  (OPORT[2]); для второго чипа с CS на другом бите OPORT условие ослаблено
  до «bit-bang включён» (правка rtl/lib/spi/spi_master_bb.v).
- `darkspi.v` не включал config.vh → при `+define+SPI` в симуляции падало
  подключение ESIMACK из darkio (SIMULATION не был виден). Include возвращён.
- darklibc printf не поддерживает `%u` — использовать `%x`/`%d`.

## Производительность и план на железо

- Bit-bang SPIBB ≈ единицы Мбит/с в лучшем случае: для 758-байтных кадров
  MSOP на боевом темпе может не хватить. Путь масштабирования:
  1) bring-up на железе как есть (bit-bang, кадры редкие);
  2) аппаратный SPI-мастер с удержанием CS на длинных транзакциях
     (darkspi поддерживает только 16/24 бита на CS — не годится для VDM;
     нужен burst-режим или новый MMIO-блок c FIFO);
  3) при потребности — quad нет у W5500, но SCK до 80 МГц у HW-мастера.
- Раскладка сокетов для полного функционала лидара (8 доступно):
  0 = MSOP TCP 50100, 1 = command TCP 50101, 2 = discovery UDP 50103,
  3 = command UDP 50101, 4 = loader TCP 50102.
- RX-путь (команды) в симуляции ещё не покрыт — добавить в модель
  RX-буфер/Sn_RX_RSR и в прошивку приём (Sn_CR_RECV) следующим шагом.
- INT-пин (M1) позволяет не поллить Sn_IR/Sn_SR — на железе завести
  на IPORT.
